# [PRD] 과제 방어전 (v1.0)
> **부제:** 마감일·예상 소요 시간 기반 대학생 전용 백워드(Backward) 일정 역산 및 집중 관리 앱

---

## 1. 문서 개요
* **문서 목적:** 컴퓨터소프트웨어학과 2학년 개인 프로젝트(9~15주차, 주 1회 실습) 기간 내 완수할 수 있는 MVP의 기능 명세, 핵심 알고리즘, 데이터 구조 및 수용 기준을 정의함.
* **대상 독자:** 개발자 본인(컴퓨터소프트웨어학과 한희재), 담당 교수님(시연 및 평가), 향후 협업 가능성이 있는 디자이너/개발자
* **작성일:** 2026년 11월 16일
* **문서 버전:** v1.0

---

## 2. 서비스 개요

### 2.1 배경 및 문제 정의 (Pain Point)
* 대학생들은 여러 과목의 과제·시험 마감일이 겹칠 때 단순 D-Day만 보고 *"아직 5일 남았네"*라며 미루다가, 실제 필요한 작업량을 간과해 마감 전날 밤샘(벼락치기)을 반복함.
* 기존 투두리스트(To-Do) 앱은 할 일을 직접 쪼개어 적어야 하므로, **오늘 당장 몇 분을 투자해야 안전한지 직관적으로 판단하기 어려움**.

### 2.2 서비스 목표
* 마감일과 예상 소요 시간, 과제 유형만 입력하면 **오늘부터 하루에 투자해야 할 권장 시간(분/시간)과 단계별 체크리스트를 자동으로 역산**해 제공함.
* 남은 여유 시간에 따라 **위기 등급(🟢/🟡/🔴)**을 시각적으로 경고하고, 내장된 집중 타이머로 실행까지 연결하여 마감 전날 밤샘을 방지함.

### 2.3 서비스 범위 (Scope)
* **[확정]** Flutter 기반 모바일 앱(Android 기준), 오프라인 로컬 저장소 기반의 과제 등록·역산 계산·체크리스트 관리·집중 타이머(MVP)

## 3. 대상 사용자
* **핵심 타깃 (Primary User): 전공 과제·실습·시험 일정이 겹치는 대학생**
  * *니즈:* 여러 과목의 마감을 놓치지 않으면서, 오늘 최소 몇 분만 투자하면 밤샘 없이 끝낼 수 있는지 명확한 행동 기준을 얻고 싶음.
* **보조 타깃 (Secondary User): 마감 기한이 있는 자격증·프로젝트 준비생**
  * *니즈:* 큰 목표를 일일 실행 단위로 쪼개고 실제 투자한 시간을 누적 기록하고 싶음.

## 5. 사용자 시나리오 및 주요 사용자 흐름

### 5.1 대표 사용자 시나리오
> 컴퓨터소프트웨어학과 2학년 B씨는 금요일 자정 마감인 '자료구조 코딩 과제'가 있다. 월요일 밤 **[과제 방어전]** 앱을 켜서 **[+ 새 과제 방어]**를 누르고, 과제명, 마감일(금요일), 예상 소요 시간(6시간), 유형(코딩 실습)을 선택한다. 앱은 자동으로 *"오늘부터 하루 1시간 12분 투자 필요 — 🟡 주의 단계"*로 분류하고 4단계 체크리스트(문제 분석 → 코드 구현 → 예외 테스트 → 보고서·제출)를 생성한다. B씨는 첫 번째 체크리스트를 선택한 뒤 내장된 **25분 집중 타이머**를 켜고 바로 코딩을 시작한다.

### 5.2 주요 사용자 흐름 (User Flow)
```text
[앱 실행 (스플래시)]
       ↓
[메인 대시보드: 방어 중인 과제 카드 리스트 (긴급도순 정렬) + 오늘의 총 권장 학습 시간]
       ├──▶ [+ 새 과제 등록] ──▶ 과제명 · 마감일 · 예상 소요 시간 · 유형 입력 ──▶ 자동 역산 및 체크리스트 생성
       │
       └──▶ [과제 카드 터치] ──▶ [과제 상세 및 방어 화면]
                                   ├── 1. 위기 등급 배지(🟢/🟡/🔴) & 오늘의 권장 투자 시간
                                   ├── 2. 단계별 체크리스트 (완료 체크 시 진행률 % 상승)
                                   └── 3. [방어 시작 (집중 타이머)] ──▶ 카운트다운/뽀모도로 실행 ──▶ 누적 시간 자동 합산
```

## 6. 기능 요구사항

### F-01. 백워드(Backward) 일정 역산 및 위기 등급 산출 (우선순위: P0 - 필수)
* **기능 설명:** 사용자가 입력한 마감일시, 총 예상 소요 시간(분), 현재까지 누적 진행 시간을 바탕으로 **오늘부터 마감일까지 매일 투자해야 하는 일일 권장 시간**을 자동 계산하고, 그 부하량에 따라 위기 등급을 부여한다.
* **핵심 계산 로직 (가정 및 제안):**
  * `잔여 필요 시간(분) = max(0, 총 예상 소요 시간 - 누적 진행 시간)`
  * `남은 일수 = max(1, 마감일 - 오늘 날짜 + 1)` *(당일 마감은 1일로 계산)*
  * `일일 권장 시간(분) = ceil(잔여 필요 시간 / 남은 일수)`
  * **위기 등급 판정 기준:**
    * 🟢 **안전 (여유):** 일일 권장 시간 60분 이하
    * 🟡 **주의 (오늘 시작 권장):** 일일 권장 시간 61분 ~ 150분(2시간 30분) 이하
    * 🔴 **위험 (밤샘 경보):** 일일 권장 시간 151분 초과 또는 마감 당일 잔여 시간 120분 이상
* **수용 기준 (Acceptance Criteria):**
  - [ ] 과제 등록 시 마감일과 예상 시간을 입력하면 저장 즉시 일일 권장 시간(분)과 위기 배지(🟢/🟡/🔴)가 정확히 계산되어 표시된다.
  - [ ] 날짜가 하루 지나거나 타이머로 누적 시간이 증가하면, 앱 재실행 또는 화면 갱신 시 일일 권장 시간과 위기 등급이 실시간으로 재계산된다.
  - [ ] 남은 필요 시간이 0분이 되거나 모든 체크리스트가 완료되면 상태가 **[방어 성공(완료)]**으로 전환된다.

### F-02. 과제 유형별 단계 체크리스트 자동 생성 및 관리 (우선순위: P0 - 필수)
* **기능 설명:** 과제 등록 시 유형을 선택하면 해당 유형에 맞는 표준 작업 단계(체크리스트)를 자동으로 생성해 주며, 사용자가 항목을 추가·수정·삭제하거나 완료 체크할 수 있다.
* **유형별 기본 템플릿 (제안):**
  * **코딩/실습:** `요구사항 분석 및 설계` → `핵심 기능 구현` → `예외 케이스 테스트 및 디버깅` → `주석 정리 및 최종 제출`
  * **레포트/글쓰기:** `주제 선정 및 자료 조사` → `목차 및 개요 작성` → `본문 초안 작성` → `오탈자 검수 및 형식 맞춤`
  * **팀플/발표:** `자료 리서치` → `발표 스크립트 구성` → `PPT 슬라이드 디자인` → `리허설 및 시간 체크`
  * **시험 공부:** `강의록·교재 1회독` → `핵심 개념 요약 정리` → `기출·연습문제 풀이` → `오답 복습`
* **수용 기준 (Acceptance Criteria):**
  - [ ] 4가지 과제 유형 중 하나를 선택해 등록하면 4개의 기본 체크리스트 항목이 자동으로 생성된다.
  - [ ] 상세 화면에서 사용자가 직접 세부 할 일을 추가하거나 기존 항목을 삭제할 수 있다.
  - [ ] 체크박스를 터치할 때마다 상단 진행률 프로그레스 바(`완료 항목 수 / 전체 항목 수 %`)가 즉시 업데이트된다.

### F-03. 내장 집중 타이머 및 누적 시간 자동 기록 (우선순위: P1 - 핵심 차별화)
* **기능 설명:** 과제 상세 화면에서 바로 집중 타이머를 실행하여 실제 작업 시간을 측정하고, 종료 시 해당 과제의 누적 진행 시간에 자동 합산한다.
* **제안 및 가정:** 1인 개발 일정을 고려하여 **25분 집중(뽀모도로)**과 **오늘의 권장 시간 맞춤 타이머** 두 가지 프리셋 버튼을 제공하는 방식을 제안함.
* **수용 기준 (Acceptance Criteria):**
  - [ ] **[25분 집중 시작]** 또는 **[오늘 목표 시간 시작]** 버튼 터치 시 카운트다운 타이머가 1초 단위로 동작한다.
  - [ ] **[일시정지]**, **[재개]**, **[기록 후 종료]** 버튼이 정상 작동한다.
  - [ ] 타이머 완료 또는 **[기록 후 종료]** 시 경과된 분(예: 25분)이 해당 과제의 `누적 진행 시간`에 즉시 합산되며, 잔여 필요 시간이 그만큼 차감된다.

### F-04. 메인 대시보드 및 과제 CRUD 관리 (우선순위: P0 - 필수)
* **기능 설명:** 등록된 모든 과제를 위기 등급 및 마감일 임박순으로 정렬하여 한눈에 보여주고, 과제 수정 및 삭제 기능을 제공한다.
* **수용 기준 (Acceptance Criteria):**
  - [ ] 메인 화면 상단에 **[오늘 방어해야 할 총 시간]**(진행 중인 모든 과제의 일일 권장 시간 합계)이 요약 표시된다.
  - [ ] 과제 리스트는 기본적으로 🔴 위험 → 🟡 주의 → 🟢 안전 → 완료 순으로 정렬된다.
  - [ ] 앱을 완전히 종료한 뒤 다시 실행해도 등록한 과제, 체크리스트 상태, 누적 집중 시간이 그대로 유지된다.

## 7. MVP 범위 (9~15주차 기준)

| 구분 | 포함 기능 (In-Scope) | 제외 기능 (Out-of-Scope / 추후 고도화) |
| :--- | :--- | :--- |
| **일정 계산** | 마감일·예상 시간 기반 백워드 일일 권장 시간 계산, 3단계 위기 등급(🟢/🟡/🔴) | 요일별 가용 시간 커스텀 설정, 공휴일/주말 제외 옵션 |
| **과제 관리** | 과제 생성·조회·수정·삭제(CRUD), 4종 유형별 체크리스트 자동 생성 | 학교 LMS(블랙보드/캔버스 등) 크롤링 자동 연동 |
| **타이머** | 25분/목표시간 카운트다운 타이머, 누적 시간 자동 합산 | 백그라운드 푸시 알림, 화이트 노이즈 사운드 재생 |
| **데이터** | 기기 내 로컬 데이터베이스 저장 (오프라인 완전 동작) | 회원가입/로그인, 클라우드 서버 동기화, 팀플 실시간 공유 |

## 8. 비기능 요구사항
* **데이터 영속성:** 앱 강제 종료나 기기 재부팅 후에도 데이터가 유실되지 않도록 로컬 영구 저장소에 즉시 커밋되어야 한다.
* **직관적 시각 피드백 (UX):** 위기 등급(🔴 `#E53935`, 🟡 `#FB8C00`, 🟢 `#43A047`)은 색맹·색약 사용자도 구분할 수 있도록 색상과 함께 텍스트 배지(`위험`, `주의`, `안전`) 및 아이콘을 병기한다.
* **타이머 정확도:** 화면이 켜져 있는 동안 타이머 오차는 1분당 ±1초 이내를 유지하며, 실수로 뒤로가기를 눌렀을 때 측정 중인 시간이 날아가지 않도록 확인 다이얼로그를 띄운다.

## 9. 데이터 및 기술 고려사항
* **개발 프레임워크:** Flutter (Dart)
* **로컬 데이터베이스 선택지 (11주차 개발 고려사항):**
  * **옵션 A (`sqflite` - SQLite):** 컴퓨터소프트웨어학과 전공 수업(데이터베이스)과 연계성이 높으며, 관계형 테이블(`tasks` 테이블, `subtasks` 테이블) 설계 역량을 교수님께 어필하기 좋음. **(추천)**
  * **옵션 B (`hive` 또는 `shared_preferences` + JSON 직렬화):** 설정이 매우 간단하고 코드량이 적어 UI 및 알고리즘 구현에 더 많은 시간을 쓸 수 있음.
* **데이터 모델 설계 예시 (`Task` & `SubTask`):**

```dart
class Task {
  final int? id;
  final String title;           // 과제명 (예: 자료구조 실습 3)
  final String category;        // 유형 (CODING, REPORT, PRESENTATION, EXAM)
  final DateTime dueDate;       // 마감일
  final int estimatedMinutes;   // 총 예상 소요 시간 (분)
  final int completedMinutes;   // 타이머로 누적된 진행 시간 (분)
  final bool isDone;            // 최종 완료 여부
}

class SubTask {
  final int? id;
  final int taskId;             // 외래키 (Task.id)
  final String title;           // 단계명 (예: 핵심 기능 구현)
  final bool isChecked;         // 체크 완료 여부
}
```

## 10. 성공 지표 (학과 프로젝트 및 시연 기준)
* **기능 완성도:** 과제 등록 → 자동 체크리스트 생성 → 타이머 측정 → 잔여 시간 및 위기 등급(🔴→🟡→🟢) 변화까지 전체 시나리오에서 **런타임 오류 0건** 달성.
* **알고리즘 검증:** 마감일이 다른 3개 이상의 테스트 케이스(당일 마감, 3일 후 마감, 14일 후 마감) 입력 시 일일 권장 시간과 위기 배지가 설계된 수식대로 오차 없이 출력됨.

## 12. 위험 요소, 미결정 사항 및 후속 논의 항목
1. **타이머 백그라운드 동작 이슈 (기술적 위험):**
   * *위험:* Flutter에서 기본 `Timer.periodic`만 사용하면 사용자가 타이머를 켜둔 채 다른 앱으로 전환하거나 화면을 끄면 OS가 타이머를 일시 정지시킬 수 있음.
   * *대응 방안:* 타이머 시작 시점의 `DateTime.now()` 타임스탬프를 저장해 두고, 화면 복귀 시 `(현재 시각 - 시작 시각)` 차이로 경과 시간을 계산하는 방식을 적용하면 백그라운드에서도 오차 없이 정확히 측정 가능함.
2. **마감 기한 초과(Overdue) 과제 처리:**
   * *미결정 사항:* 마감일이 이미 지난 미완료 과제를 🔴 위험 최상단에 유지할지, 별도의 `[마감 초과]` 배지로 분리할지 결정 필요.
3. **일일 권장 시간 계산 기준일:**
   * *미결정 사항:* 늦은 밤(예: 오후 10시 이후)에 과제를 등록할 때 '오늘'을 작업 가능 일수에 포함할지, 익일 기준으로 계산할지 결정 필요.
