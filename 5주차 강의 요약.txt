1. 상태(State)의 기본 개념
--------------------------------------------------
- 핵심 용어:
  • 상태(State): 현재 화면을 결정하는 '값'
  • 이벤트(Event): 사용자가 누르거나 입력하는 '행동'
  • 화면(UI): 현재 상태 값을 보여주는 '부분' (상태 -> 화면)
- StatefulWidget vs State:
  • StatefulWidget: 바뀔 수 있는 화면의 큰 틀 정의
  • State: 실제로 바뀌는 값(완료 여부 등)을 기억
- setState()의 역할:
  • State 안에서 값이 바뀔 때 setState()를 호출해야 Flutter가 화면을 다시 그림(build).
- 계산된 상태:
  • 원본 값(_done)이 바뀌면 남은 할 일 수(_remaining)는 계산식(.where().length)을 통해 화면에 자동 반영됨.
- 단방향 데이터 흐름:
  • 자식 위젯은 부모에게 이벤트(변경 요청)를 전달하고, 부모는 바뀐 상태값을 다시 자식 위젯에게 넘겨줌.

2. AI 작업 맥락 (Context Engineering)
--------------------------------------------------
- 컨텍스트 엔지니어링 개념:
  • 프롬프트(지시문)뿐만 아니라 AI가 작업할 파일, 규칙/제약, 도구, 검증 결과(인수 조건: AC)까지 전체 자료 구조를 설계하는 것.
- AI에게 요청 시 필수 전달 항목 (6가지):
  1) 목표 (무엇을 만들지)
  2) 현재 상태 (무엇이 이미 있는지 - main.dart 코드 등)
  3) 근거 (어느 자료가 맞는지)
  4) 제약 (새 패키지/서버 추가 금지 등)
  5) 도구 (flutter analyze 등)
  6) 인수 조건 (AC1~AC3 완료 기준)

3. 완료 버튼 검증 & 인계 (AC1 ~ AC3)
--------------------------------------------------
- 검증 4단계:
  1) 요구사항 확인 (두 번 누르면 원복 등)
  2) 코드 작성 (_toggleDone)
  3) 화면 확인 (문구, 아이콘, 남은 수 변화)
  4) 증거 확보 (AC 캡처 및 flutter analyze 오류 0건 확인)
- 작업 인계 기록:
  • AI가 완료했다고 해도 실제 앱 화면과 'flutter analyze' 결과를 직접 확인하고 완료/미완료/증거를 문서로 남김.
